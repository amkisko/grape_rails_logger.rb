Recorded 2026-09-15. Library gem. Grape 4.0.0 is on the registry. Gemspec ceiling was grape < 4.0, which blocked 4.x. Grape 4 moved http_methods, path, and api off the public endpoint options Hash. extract_action still read options[:method] and options[:path], so request log action names became unknown. Appraisal gemfiles also listed gem grape >= 1.6 beside the path gemspec, which put grape (>= 1.6) in Bundler DEPENDENCIES.

## Participants

- amkisko

## Decisions

- Cut 1.2.2 and raise the grape runtime ceiling to < 5.0.
- Read definition-time verbs and path from protected Endpoint#config, with the grape 3 options Hash as fallback.
- Read the owning API from endpoint.api, with options[:for] as fallback.
- Drop the extra grape pin from Appraisals and generated gemfiles. Keep gemspec path: "../".
- Relock grape to 4.0.0 in Gemfile.lock and appraisal lockfiles.
- Prove action names with a grape 4 config example and live POST /users and GET /users/:id.

## Effects

- VERSION is 1.2.2. CHANGELOG.md has a 1.2.2 section.
- Gemspec allows grape >= 1.6, < 5.0.
- Appraisal gemfiles and generated gemfiles no longer declare grape (>= 1.6) as a direct Bundler dependency. gemspec path: "../" remains. Appraisal lock DEPENDENCIES list grape_rails_logger! without grape (>= 1.6).
- Gemfile.lock and appraisal lockfiles resolve grape 4.0.0.
- extract_action reads protected Endpoint#config for grape 4, with options Hash fallback for grape 3. extract_format_from_content_type reads endpoint.api first.
- make test on main: rubocop 55 files no offenses, rbs validate, polyrun parallel-rspec 5 workers exit 0, bundle exec rspec spec/integration 4 examples 0 failures.
- make audit on Gemfile.lock and gemfiles/rails72, rails8ruby34, rails8ruby4: No vulnerabilities found. ruby-advisory-db commit f08b5bf5b2778201db0b69f0faa7a407e2476cb8, last updated 2026-09-13.
